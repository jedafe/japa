# Form Field Type Mismatch Audit — Control & Admin Panels

Date: 2026-07-19
Scope: apps/control, apps/admin
Focus: Form fields using incorrect component types (text inputs where Select/MultiSelect/Textarea/Number should be used)

---

## CONTROL PANEL

### ISSUE 1 — Settings "All Categories" view missing component types (HIGH)

**File:** `apps/control/src/routes/settings/+page.svelte`  
**Lines:** ~838–915 (grouped "All" view template block)

The single-category view handles all 6 component types (`switch`, `select`, `multi-select`, `textarea`, `number`, `text`). The "All Categories" grouped view only handles `switch`, `select`, and sensitive keys — falling through to a plain `<input type="text">` for everything else.

| Setting Key | Expected Type | Actual in "All" View | Should Be |
|---|---|---|---|
| `i18n.enabled_languages` | `multi-select` (csv of language codes) | `text` input | Multi-select (same as single-category view) |
| `media.allowed_video_types` | `multi-select` (csv of video types) | `text` input | Multi-select (same as single-category view) |
| `general.site_description` | `textarea` | `text` input | `<textarea>` (same as single-category view) |
| `cors.allowed_origins` | `textarea` | `text` input | `<textarea>` (same as single-category view) |
| `content.link_preview.blacklist` | `textarea` | `text` input | `<textarea>` (same as single-category view) |
| All `int`/`float` type settings | `number` input | `text` input | `<input type="number">` |

**Root cause:** The "All Categories" `{#if}` chain missing: `multi-select`, `textarea`, and `number` branches.

**Fix:** Add the three missing `{:else if}` branches in the "All Categories" template block, mirroring the logic already present in the single-category view.

### ISSUE 2 — Control API Keys: scopes field uses comma-separated text input (MEDIUM)

**File:** `apps/control/src/routes/api-keys/+page.svelte`  
**Lines:** ~355 (create), ~435 (edit)

```svelte
<!-- Current: -->
<input type="text" bind:value={createForm.scopes} placeholder="read,write,admin" />
```

| Field | Current Component | Data Type | Should Be |
|---|---|---|---|
| `createForm.scopes` | `<input type="text">` with placeholder `"read,write,admin"` | `string[]` | Multi-select with predefined scope options (`read`, `write`, `admin`, `moderate`, `system`) |
| `editForm.scopes` | `<input type="text">` with placeholder `"read,write,admin"` | `string[]` | Multi-select with predefined scope options |

**Problem:** Scopes are an `AdminApiKey.scopes: string[]`. Users manually type comma-separated values into a text input — error-prone, no validation of valid scope names.

**Fix:** Replace text input with a chip/tag-based multi-select using known scope constants.

### ISSUE 3 — Control Settings: custom multi-select uses single Select as a picker (LOW)

**File:** `apps/control/src/routes/settings/+page.svelte`  
**Lines:** ~663–713

The multi-select workaround uses `Select.Root type="single"` where selecting an option appends it to a comma-separated string. This works functionally but is not a proper multi-select. Users can only add one option at a time. Consider a proper checkbox-in-dropdown component if Bits UI supports it.

## ADMIN PANEL

### ISSUE 4 — Admin Tickets: status and priority are free-text inputs (HIGH)

**File:** `apps/admin/src/routes/tickets/+page.svelte`  
**Lines:** ~365–370

```svelte
<!-- Current: -->
<label for="tk-status" ...>{t("common.status", "Status")}</label>
<input id="tk-status" type="text" bind:value={editForm.status} ... />

<label for="tk-priority" ...>{t("tickets.priority", "Priority")}</label>
<input id="tk-priority" type="text" bind:value={editForm.priority} ... />
```

| Field | Current | Should Be | Values |
|---|---|---|---|
| `editForm.status` | `<input type="text">` | `<Select>` | `open`, `in_progress`, `resolved`, `closed` |
| `editForm.priority` | `<input type="text">` | `<Select>` | `low`, `medium`, `high`, `urgent` |

**Problem:** Users can type any string for status/priority — invalid values stored.

**Fix:** Replace both text inputs with the app's `<Select>` component with predefined options.

### ISSUE 5 — Admin Settings: missing field types (HIGH)

**File:** `apps/admin/src/routes/settings/+page.svelte`  
**Lines:** ~142–172

The settings page only handles 4 types: `text`, `number`, `toggle`, `select`. Missing:

| Missing Type | Should Render As |
|---|---|
| `textarea` | `<textarea>` |
| `multiselect` | MultiSelect component |
| `rich_text` | Rich text editor |
| `boolean` | Checkbox/Toggle |
| `upload` | File upload component |

Backend can return settings with these types — they currently render nothing or fall through to text.

**Fix:** Add the missing type handlers in the `{#if setting.type === ...}` chain.

### ISSUE 8 — Admin: No MultiSelect component exists (LOW)

**Location:** `/apps/admin/src/lib/components/ui/` — only `select.svelte` exists, no `multi-select.svelte`

Multi-value selection is handled ad-hoc through checkbox patterns in:
- `routes/users/[userId]/+page.svelte` — group selection uses checkboxes
- `routes/users/roles/+page.svelte` — permission selection uses checkboxes
- `routes/users/groups/+page.svelte` — permission selection uses checkboxes
- `routes/webhooks/+page.svelte` — events selection uses toggle-button grid

**Fix:** Create a `MultiSelect` component using Bits UI `Select.Root type="multiple"` in `/apps/admin/src/lib/components/ui/multi-select/`.
