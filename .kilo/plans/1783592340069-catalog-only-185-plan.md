## Root Cause Analysis

The 185 CATALOG_ONLY routes break down into 3 categories:

### Category A: Prefix Mismatches (27 routes)
Catalog says `/admin/X` but code has `/X` (no admin prefix). The routes exist in code but under different paths.

**Decision needed:** Update catalog to match code (recommended — avoids breaking existing frontend callers).

### Category B: Routes Needing New Handler Methods (61 routes)
These routes don't exist in code at all AND the target package lacks a matching handler.

### Category C: Routes Needing Wiring Only (97 routes)
The target package has a handler method that can serve the route, but it's not wired in `server.go`.

## Risks

1. **Handler signature mismatches** — Some handler methods may not match the route's expected request/response shape. Verify each handler's signature before wiring.
2. **Permission keys** — New admin routes may need new RBAC permission keys added to `bootstrapPermissions()`.
3. **Feature gates** — Some routes may need to be gated behind feature flags (e.g., `feature.comparison`).
4. **Frontend breakage** — Wiring admin routes at new paths may break frontend callers that expect the old `/admin/` prefix.
